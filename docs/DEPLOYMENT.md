# Deployment

The live demo runs entirely on free tiers:

| Piece | Host | Notes |
|---|---|---|
| REST API | [Render](https://render.com) web service (Docker) | Defined in [`render.yaml`](../render.yaml). Free instances sleep after 15 minutes idle, so the first request after a pause takes about a minute |
| PostgreSQL | [Neon](https://neon.tech) | Schema and demo data are created by Flyway on the API's first start |
| Storefront | [Vercel](https://vercel.com) | Static Vite build of `client/` |
| Email | [Brevo](https://www.brevo.com) SMTP relay | Activation codes and order confirmations |

Deploy in this order: the API URL is baked into the storefront build, and the storefront URL is needed by the API for CORS and email links.

## 1. Database (Neon)

1. Create a project; region **AWS Asia Pacific (Singapore)** to sit next to the API.
2. Open **Connect**, turn **Connection pooling off** (Flyway and Hikari need a direct connection), and note the host, database, user and password.

## 2. Email (Brevo)

1. **Senders, domains & dedicated IPs → Senders**: add and verify the address emails will come from. This is `EMAIL_FROM`.
2. **SMTP & API → SMTP**: note the SMTP login (`EMAIL_SENDER`) and generate an SMTP key (`EMAIL_SENDER_PASSWORD`).

## 3. Staff password

The README publishes the local staff login, so the live demo needs its own. Generate a BCrypt hash of a private password:

```bash
htpasswd -bnBC 10 "" 'your-private-password' | tr -d ':\n'
# or, without htpasswd:
docker run --rm httpd:2.4-alpine htpasswd -bnBC 10 "" 'your-private-password' | tr -d ':\n'
```

The output (starting `$2y$10$`) is `DEMO_STAFF_PASSWORD_HASH`.

## 4. API (Render)

1. **New → Blueprint**, connect this GitHub repository and select `render.yaml`.
2. Fill in the prompted values:

   | Variable | Value |
   |---|---|
   | `PGHOST`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` | From Neon (direct connection) |
   | `CORS_ALLOWED_ORIGINS`, `STOREFRONT_URL`, `ACTIVATE_ACCOUNT_URL` | The storefront URL you will use on Vercel, e.g. `https://easybuy-store.vercel.app` (no trailing slash) |
   | `EMAIL_SENDER`, `EMAIL_SENDER_PASSWORD` | Brevo SMTP login and key |
   | `EMAIL_FROM` | The verified Brevo sender |
   | `DEMO_STAFF_PASSWORD_HASH` | From step 3 |

   `JWT_SECRET_KEY` is generated by Render.
3. Deploy, then check `https://<service>.onrender.com/actuator/health` returns `{"status":"UP"}`.

## 5. Storefront (Vercel)

1. **Add New → Project**, import this repository.
2. **Root Directory**: `client`. The Vite preset is detected automatically.
3. **Environment Variables**: `VITE_API_BASE_URL` = the Render URL, e.g. `https://easybuy-api.onrender.com`.
4. Deploy. If Vercel assigned a different domain than the one entered in step 4, update the three storefront variables on Render; it redeploys automatically.

## 6. Smoke test

1. Open the storefront and log in as `demo` / `Demo1234!`.
2. Add a product to the cart and complete checkout.
3. Register a new account with a real inbox: the activation code arrives from `EMAIL_FROM`.

## Operations

- **Deploys**: pushing to `main` redeploys both the API (Render) and the storefront (Vercel). CI runs on every pull request.
- **Migrations**: Flyway applies new `db/migration` scripts on startup; Hibernate validates the schema, so a mismatched build fails fast instead of serving errors.
- **Health**: `/actuator/health` reflects the API and its database. Email is best effort and does not affect health.
